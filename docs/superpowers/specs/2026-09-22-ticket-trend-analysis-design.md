# 客服工单趋势分析设计

## 目标

把 50 条客服工单转成一个可双击打开的中文静态 Dashboard，帮助主管快速识别数量趋势、问题结构、处理效率和需要优先跟进的异常。

## 交付形态

- `index.html`：构建后的单文件 Dashboard，不依赖服务器和第三方 CDN。
- `src/`：分析逻辑、工单数据与页面渲染源码。
- `data/tickets.json`：保留原始输入数据，便于追溯。
- `README.md`：分析维度、关键发现、异常判断依据、AI 使用情况与运行方式。
- `outputs/`：开发过程截图与运行结果截图。

## 分析维度

1. 时间趋势：按日看工单量，识别近期是否升温以及峰值日期。
2. 类型分布：看类别占比、未解决量和平均处理时长，决定资源优先级。
3. 优先级与解决状态：关注高优先级积压，判断风险是否集中在关键工单。
4. 处理效率与满意度：比较平均处理时长和平均满意度，定位体验恶化的类别。
5. 渠道与问题关联：比较在线/电话结构，并用关键词与描述辅助发现重复问题簇。

## 判断规则

- 高优先级未解决：直接进入“立即关注”。
- 处理时长 >= 48 小时：标记为长时处理。
- 满意度 <= 2：标记为低满意度。
- 类别风险：按“未解决率、平均处理时长、平均满意度”综合排序，避免只看数量。
- 趋势：使用首日与末日工单量、最高日工单量以及最近 3 日均值展示，不把短样本强行解释成统计显著性。

## 页面结构

顶部为标题和数据范围；第一屏给出总量、未解决、高优先级、平均满意度；中部为日趋势和类别分布；下部为优先级/渠道/效率对比、异常清单与全部工单筛选表。异常清单支持按“全部、未解决、长时处理、低满意度”切换，便于截图和复核。

## 验证策略

使用 Node 内置测试验证总数、核心聚合值和异常识别结果，再用构建脚本生成单文件 HTML，并用本地浏览器检查页面渲染。
